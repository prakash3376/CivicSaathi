# CivicSaathi

Multilingual policy, rights and scheme explainer. Product spec: `SPEC.md`. Setup: `README.md`. Layers and conventions: `docs/ARCHITECTURE.md`. Official data sources: `docs/DATA_SOURCES.md`. The AI assistant: `docs/ASSISTANT.md`. Eligibility and the scheme rules: `docs/ELIGIBILITY.md`. Voice and the three languages: `docs/VOICE.md`. The home page, sectors, search, policy and profile pages: `docs/PORTAL.md`.

FastAPI backend in `backend/`, React 19 + Vite + TypeScript frontend in `frontend/`. The project is built in phases: do only the phase the user asks for. Phase 1 (scaffold, config, health check), Phase 2 (official data ingestion into ChromaDB) and Phase 3 (AI assistant and RAG: Gemini, retrieval, English/Bengali answers, citations, freshness, prompt-injection protection), Phase 4 (eligibility engine: scheme rules as data, three outcomes, document checklist) and Phase 5 (frontend: catalogue, scheme details, chat, eligibility form, result and checklist, responsive) and the voice and Hindi work (listen, speak a question, English/Bengali/Hindi everywhere) are done.

## Verify a change

Backend, from `backend/` (the venv is `.venv`; on Windows call `.\.venv\Scripts\python.exe` instead of activating it):

```
python -m ruff check . && python -m ruff format --check . && python -m mypy && python -m pytest
```

Frontend, from `frontend/`:

```
npm run lint && npm run typecheck && npm test && npm run build
```

Dev servers: `python -m uvicorn app.main:app --reload` (port 8000) and `npm run dev` (port 5173, proxies `/api`).

Ingestion (from `backend/`): `python -m app.cli sources | verify | ingest | search "question"`. Scheme rules: `python -m app.cli schemes` (load and list) and `schemes-check` (every quote is still in its indexed document). Assistant: `python -m app.cli ask "question"` and `python -m app.cli assistant-check` (index, API key, and a live Gemini probe in English and Bengali). `python -m pytest -m live` runs the tests that need the internet, the real embedding model or a Gemini key (`tests/test_live.py`, `tests/test_live_assistant.py`); they are off by default, and the Gemini ones skip without `GEMINI_API_KEY`.

## Conventions

- Backend errors use the envelope in `app/core/errors.py`. Raise `AppError` subclasses; never put submitted values in an error body. Ingestion code raises the domain errors in `app/domain/errors.py` instead.
- Never log document text, questionnaire answers or uploads (SPEC AC9).
- Pipeline code goes in `backend/app/services/<stage>/`, one package per SPEC section 6 step. Routers stay thin and `services` never imports from `api` or `cli`. Types shared between stages live in `app/domain/`.
- New settings: add a field in `app/core/config.py` and a documented line in `backend/.env.example`.
- Sources are added only through `backend/data/sources/*.toml`, after a person has opened the URL. Run `verify` before `ingest`. Never disable certificate verification; a source that needs an exception gets an explicit, explained `legacy_tls = true`. A failed verification must never modify the index.
- Anything under `backend/storage/` is derived data and safe to delete. A chunk's text must remain an exact slice of `ParsedDocument.text` (its offsets are used to highlight the original).
- If the index's embedding model changes, indexes must be rebuilt (`ingest --rebuild`); the store refuses to mix models.
- Assistant code is in `services/{safety,grounding,llm,assistant}`. Nothing the model writes reaches a user unless `grounding.verify` accepts it (exact quote found, every figure, month and address in the quote, right language). Refusals, the disclaimer and warnings are fixed texts in `services/assistant/messages.py` (English and Bengali), never model output. Never log a question, a passage or a model reply: counts and codes only. Personal numbers are removed from a question before the model sees it.
- General guidance (`services/assistant/guidance.py`, `docs/ASSISTANT.md`) is the one place model text reaches a user without a quote, so it stays narrow: always behind the fixed `guidance_intro`, never with a citation, never with a figure, address, rule or eligibility decision, every sentence passing `check_guidance`, and any failure ends in the fixed `not_covered` text. Greetings are rules (`smalltalk.py`), not the model. Never let guidance replace or sit beside a checked claim.
- `VectorStore` stamps `last-update` on every change and a reader reopens the index when it sees a new stamp: the API keeps the index open while `ingest` rewrites it, and a stale handle fails (measured). Change the index only through its methods.
- Tests must not depend on a developer's `backend/.env`: build `Settings(_env_file=None)`, or set `GEMINI_API_KEY=""` in the environment when using `get_settings()` (a real key there would otherwise make a "no key" test call Gemini).
- The Bengali and Hindi texts (`services/assistant/messages.py`, `data/schemes/*.toml`, and the `strings.ts` tables of the frontend) are drafts by a non-native speaker and need a native speaker's review.
- Frontend: `@/` alias for `src/`; server state through TanStack Query hooks inside `features/*`; colors only from the tokens in `src/styles/index.css`; keep `npm run lint` (includes jsx-a11y) at zero warnings; touch targets at least 48px.
- Eligibility (`services/eligibility`) is a pure function of rules and answers: no model, no clock, no randomness. Scheme rules are data in `backend/data/schemes/*.toml`, each statement with a verbatim quote; the loader refuses a figure, month or address in the wording that its quote lacks. Unknown (a skipped question) is never turned into met or not met, and "eligible" needs every question answered (SPEC AC5/AC6). Never log or store a questionnaire answer; errors name the question id, never the value. Run `schemes-check` after any rule or source change; boundaries follow the document's words (`lt` for "less than", `lte` for "not more than").
- Frontend language: one interface language (`i18n/LanguageProvider`, header switch: `en`, `bn`, `hi`), a typed table of words per area with parity tests for every language, scheme text picked with `local()`; figures use the digits 0-9 in every language. A new language needs an entry in every table, in `LocalText`, in the scheme TOML, in `messages.py`, the script check in `grounding/language.py` and the prompt names. The chat transcript and questionnaire answers live in memory only; `localStorage` holds only the language choices and the reading speed.
- Voice runs in the browser (`features/voice`): `speechSynthesis` to read text, `SpeechRecognition` to take a question, nothing on the server. A text is read only with a voice for its language, else the page says so (R8); the microphone fills the question box and never sends by itself; say where the audio goes (the browser maker's service) next to the microphone and never log or store it. Tests use the fakes in `src/test/speech.ts`. The voice conversation (`VoiceConversation`) moves on from callbacks (speech ended, answer arrived, listening ended), never from effects that set state, and every callback checks the session number so a late one after Stop does nothing; keep it that way.
- Portal (`docs/PORTAL.md`): a scheme names its `sector` in its TOML and the loader refuses an unknown one; sector pages are one component driven by data, and a sector with no scheme shows the empty state, never filler. Never show a deadline, date, benefit amount or update that the documents do not carry. Nothing on a page may be a button that does nothing: what is not built is said in words.
- Reliability (`docs/RELIABILITY.md`): the model is always behind `GuardedModel` (circuit breaker) and `GeminiClient`'s own retry loop (total deadline, jitter, `Retry-After`; a wrong key is never retried). Every model failure code in `FALLBACK_CODES` ends in `200` with the matching passages, never an error shown to a citizen; the cause goes to `stats.note_failure`, never to the reader, and what the provider said is never logged. Only one ingestion runs at a time (`IngestLock`); `ingest --rebuild` snapshots the index and reads the copy back first, and `index-restore` is the way back. A source is "unchanged" only when the audit record *and* the index match the document. Nothing deletes or repairs an index, record or document automatically (`index-check` is read-only). A new page goes under the route-level `errorElement`; an independent heavy section gets a `SectionBoundary`. Failure tests are named `*resilience*` (frontend) or live in the files listed in `scripts/reliability.py`; inject failures through a transport, a stub or a fake model, never by patching the code under test. Run `python scripts/reliability.py` before a release: a step that could not run is BLOCKED, never a pass.
- Versions are pinned: backend in `requirements*.txt` and `constraints.txt` (install with `-c constraints.txt`), frontend by `package-lock.json`. TypeScript is 7.x and linting is Oxlint, because `typescript-eslint` does not support TypeScript 7 yet. Backend tests use `httpx2`, which Starlette's `TestClient` now prefers over `httpx`.
- When writing source with the editor tools, write non-ASCII characters as `\N{NAME}` or `\U0000XXXX` in Python (also inside regexes), never `\uXXXX`; in TypeScript use the braced `\u{XXXX}`. The 4-digit form is converted into the literal character when the file is written, which makes invisible characters in source and can make a test pass vacuously.
